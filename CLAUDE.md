# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Honu is a macOS app written in Swift 6 with **SwiftUI** (hosted in AppKit) — an experiment in desktop GUI design that departs from macOS conventions. Liquid Glass bubbles float directly on the real desktop, above all other windows. It starts with only a pixel-art turtle in the bottom-left corner; clicking it opens a menu whose items make it spit out bubbles (a note, or a web page that can also play YouTube videos), and dragging a bubble calls up a pixel-art octopus that deletes it if dropped on. It needs macOS 26 or newer, for Liquid Glass (`glassEffect`) and SwiftUI's `WebView`. The turtle's place, the bubbles, and their items persist across launches in `~/Library/Application Support/Honu/state.json` (delete it to reset).

Honu was first written in Rust with egui; that version is in the git history before the switch to Swift, and what it had that this one lacks (Ask AI, physics, breathing and gestures) is listed in `TODO.md`.

## Commands

```sh
swift build                  # build
swift run                    # build and launch; bubbles float on the real desktop (quit with ⌘Q)
swift build -c release       # optimized build
swift format lint --strict -r Sources Package.swift   # lint (as CI does)
swift format -i -r Sources Package.swift     # format
```

CI (`.github/workflows/ci.yml`) runs on a `macos-26` runner for every push to `main` and every pull request: the strict format check (`swift format lint --strict`, so warnings fail), a debug build, and a release build.

`.swift-format` sets 4-space indentation and 100-column lines. The project is a Swift package, so it builds with the Command Line Tools alone; Xcode is not needed. The Command Line Tools do not ship SwiftUI's macro plugins, so **`@State` and other SwiftUI macros do not compile**: spell state out as a stored `State` value instead (`private let player = State(initialValue: Player())`, read through `wrappedValue`), or keep it in an `@Observable` model (Observation's macros do ship). `swift run` launches a bare executable, not an app bundle; the Dock icon is set at launch from `Sources/Honu/Resources/icon.png`.

## Architecture

The code follows MVC. Each **microapp** (Notes, Web) is a controller that keeps its own model: any number of items, such as notes. A **bubble** is only a view of one item, pointing at it by id. The **shell** wires microapps, the stage of bubbles, and the two sprites (the turtle and the octopus) together. Models are `@Observable` classes on the main actor, so SwiftUI views redraw when what they read changes.

- `Sources/Honu/main.swift`: starts `NSApplication` with `AppDelegate` as a regular app (Dock icon and menu bar).
- `Sources/Honu/AppDelegate.swift`: sets the Dock icon and the menu bar (Quit and the Edit commands, which text fields need), creates the `Shell` and the `FloatingWindow` covering the main screen's visible frame (everything but the menu bar and Dock), and starts `ClickThrough`. A local event monitor hands the shell what SwiftUI's gestures do not cover: presses on content AppKit views take for themselves (to raise that bubble), right-clicks on the turtle (opening its menu), Escape (closing it), and ⌘Z (undoing a delete, unless a text field is first responder). It saves once more when Honu quits.
- `Sources/Honu/FloatingWindow.swift`: `FloatingWindow`, a transparent, borderless, shadowless window at the floating level on every Space, hosting `ShellView` in an `NSHostingView` that does not resize the window to fit. It can become key, which borderless windows refuse by default but text fields need. `ClickThrough` runs 60 times a second: it calls `Shell.tick` and lets clicks through to the apps below except where `Shell.takesClick(at:)`; a window that ignores mouse events gets none, so it polls the global mouse position to decide.
- `Sources/Honu/Shell.swift`: `Shell`, the controller of the whole app: the `Registry` of microapps, the `Stage`, the `Turtle`, the `Octopus`, and where the turtle's menu is open. What is under a point is one `Hit`, from the top layer down: the open menu (which takes every click, like a native menu), the turtle, the octopus, then the bubbles. Clicking the turtle hops it and opens the menu there; a menu item starts a new item in its microapp (`start`), and the turtle spits out a bubble showing it. Dragging a bubble more than `summonDistance` calls up the octopus; with the pointer within its reach the bubble shrinks, and letting go there swallows it. `undoDelete` has the octopus spit the latest one back. `tick` deletes for good the bubbles the octopus forgets (and their items, once no bubble shows them) and autosaves.
- `Sources/Honu/MicroApp.swift`: the `MicroApp` protocol and what goes with it. A bubble's `ViewTarget` (`AppID` + `ItemID`) names one item, so a microapp can have any number of bubbles. A microapp gives its items' `appearance` (glass tint, symbol, sizes, text color), `title` (the bubble label), and the SwiftUI `content` of an open bubble. Each bubble also owns a view state its microapp makes for it (`newViewState`), for what belongs to that one view rather than to the item, such as whether it still has to take the focus. A microapp lists its `items` and saves and loads them as JSON, keeping their ids (`ItemIDs.skip(past:)` keeps new ids after restored ones). To add a microapp, implement the protocol in `Sources/Honu/Apps/` and list it in `Shell.init`.
- `Sources/Honu/Apps/NotesApp.swift`: the Notes microapp, any number of notes, each a `TextEditor` on yellow-tinted glass; a new note's bubble takes the focus when it opens. A note's bubble is labeled with its first line with text (`shortLabel` keeps labels short).
- `Sources/Honu/Apps/WebApp.swift`: the Web microapp, any number of pages. A new page asks for a link, then shows it in SwiftUI's `WebView`; YouTube links (`youTubeID`) play in `YouTubeView`, YouTube's embedded player loaded from an HTML page with a base URL, because the player refuses to play without a referring origin.
- `Sources/Honu/Stage.swift`: `Bubble` (the view model of one bubble: its target, center, whether open, and its flight, doomed, and swallowed state) and `Stage`, every bubble in back-to-front paint order. The stage hit-tests, raises, drags (the dragged bubble stays on top, and new bubbles go below it), opens and closes bubbles with a springy morph (`toggle`), spits out new ones (`spitPanel`: a bubble flies out of the turtle's mouth, small, grows on the way, and opens on landing, stepping aside from a panel already there, as windows cascade), and sends them into the octopus and back. Swallowed bubbles stay on the stage, out of sight, until the octopus forgets them. It knows nothing of what a bubble shows.
- `Sources/Honu/Persistence.swift`: `Autosave` keeps the turtle's place, which bubbles show which items, where (relative to the screen center), and whether open, plus each microapp's own JSON. It checks once a second and writes only what changed. `restore` puts it all back when the shell starts, without the focus, and deletes items no bubble showed, such as one still in the octopus.
- `Sources/Honu/Sprites/Sprite.swift`: `PixelGrid`, a character-grid sprite (one character per pixel, `spritePixel` points square), painted by `SpriteCanvas` as crisp squares; `PixelMask` makes hit-testing skip transparent pixels. Sprite animations run on the `now()` clock.
- `Sources/Honu/Sprites/Turtle.swift`: the turtle, which starts in the bottom-left corner and can be dragged anywhere on screen. It bobs while idle, hops when clicked, and briefly opens its mouth (`spit`) for each bubble.
- `Sources/Honu/Sprites/Octopus.swift`: the octopus. It rises from the bottom edge, in the corner away from the turtle, while summoned or while a swallowed bubble can still come back, and sinks again afterwards. Whether the *pointer* is within `reach` decides a drop, not where the bubble is. It remembers swallowed bubbles for `undoSeconds`, showing "Click to undo"; clicking it or the hint, or ⌘Z, spits the latest back to where it was picked up.
- `Sources/Honu/Views/`: the SwiftUI views. `ShellView` stacks the bubbles, the octopus, the turtle, and the open menu (over a nearly transparent layer, so a press outside closes it) in the `stage` coordinate space. `StageView` puts every bubble in one `GlassEffectContainer`, so bubbles that come close blend into each other. `BubbleView` draws a bubble as interactive Liquid Glass with its title or symbol, or, open, its title over its microapp's content; dragging moves it and double-clicking toggles it. `TurtleView` and `OctopusView` animate the sprites with `TimelineView`. `TurtleMenu` is a glass menu with one item per microapp and Exit.

## Conventions

- Everything in the repository must be in English: identifiers, comments, UI strings, docs, and commit messages — even when the conversation is in Chinese.
- After changing Swift code, run `swift build` and `swift format lint -r Sources Package.swift` before reporting the work as done, and fix any warnings they raise.
- The Claude API key lives in `.env` at the repository root as `ANTHROPIC_API_KEY` (the name the Anthropic SDKs read). `.env` and `.env.*` are git-ignored; only the empty template `.env.example` is committed. Never read, print, or commit `.env`, and never put a key anywhere else in the repository.
