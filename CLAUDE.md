# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Honu is a macOS app written in Swift 6 with **SwiftUI** (hosted in AppKit) — an experiment in desktop GUI design that departs from macOS conventions. Liquid Glass bubbles float directly on the real desktop, behind the other apps' windows until the user clicks one of them (the UI's design is in `docs/UI.md`). It starts with only a pixel-art turtle in the bottom-left corner; clicking it opens a launcher of tiles that make it spit out bubbles (a microapp built into Honu, from the **Reef** folder: a note, or one written as a web page, such as the Timer; a microapp Claude has written; or **+**, a new microapp Claude writes from a description), right-clicking it opens a menu with Show on All Desktops (Honu on every Space, as it starts, or only the one it was launched on) and Exit, and dragging a bubble calls up a pixel-art octopus that deletes it if dropped on, as dragging a microapp's tile there uninstalls the microapp. Every launch is a new instance with data of its own. The launcher's design and plan are in `docs/Launcher.md`, and its Reef of built-in microapps in `docs/BuiltinApps.md`. It needs macOS 26 or newer, for Liquid Glass (`glassEffect`) and SwiftUI's `WebView`. The turtle's place, the bubbles, and their items persist across launches in `~/.honu/state.json` (delete it to reset; `~/.honu/` is also where Claude Code runs), or in the file `HONU_STORE` names, so a development run can keep bubbles of its own.

Honu was first written in Rust with egui; that version is in the git history before the switch to Swift.

## Commands

```sh
swift build                  # build
swift run                    # build and launch; bubbles float on the real desktop (quit with ⌘Q)
HONU_STORE=/tmp/honu.json swift run   # same, saving to a store of its own
swift build -c release       # optimized build
swift test                   # run the tests in Tests/HonuTests
swift test --filter <name>   # run tests whose name matches
swift format lint --strict -r Sources Tests Package.swift   # lint (as CI does)
swift format -i -r Sources Tests Package.swift     # format
```

CI (`.github/workflows/ci.yml`) runs on a `macos-26` runner for every push to `main` or `dev` and every pull request: the strict format check (`swift format lint --strict`, so warnings fail), a debug build, the tests, and a release build. `.github/workflows/pages.yml` publishes Honu's web page, `site/index.html` with the images in `docs/images/` beside it in `images/`, to GitHub Pages at openhonu.ai whenever a push to `main` changes them.

Two hooks run the same checks earlier. `.githooks/pre-push` (on once `git config core.hooksPath .githooks` is set; Git does not turn on a repository's hooks by itself) runs the strict lint and the tests before a push that changes `Sources/`, `Tests/`, `Package.swift`, `Package.resolved`, or `.swift-format`, retrying `swift test` with Swift Testing's plugin path when SwiftPM loses it. A Claude Code `PostToolUse` hook in `.claude/settings.json` lints each Swift file Claude writes or edits and hands the errors back, so they are fixed as they appear; it does not run the tests, which are still to be run before reporting work as done.

`.swift-format` sets 4-space indentation and 100-column lines. The project is a Swift package, so it builds with the Command Line Tools alone; Xcode is not needed. The Command Line Tools do not ship SwiftUI's macro plugins, so **`@State` and other SwiftUI macros do not compile**: spell state out as a stored `State` value instead (`private let player = State(initialValue: Player())`, read through `wrappedValue`), or keep it in an `@Observable` model (Observation's macros do ship). With the Command Line Tools alone, SwiftPM sometimes fails to hand the compiler Swift Testing's macro plugin, and `swift test` fails with "plugin for module 'TestingMacros' not found"; pass it by hand: `swift test -Xswiftc -plugin-path -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing`. `swift run` launches a bare executable, not an app bundle; the Dock icon is set at launch from `Sources/Honu/Resources/icon.png`.

## Architecture

The code follows MVC. Each **microapp** (Notes, Ask AI, Web, each page built in, and Maker; Ask AI and Web keep their items but are left off the launcher for now) is a controller that keeps its own model: any number of items, such as notes. A **bubble** is only a view of one item, pointing at it by id. The **shell** wires microapps, the stage of bubbles, and the two sprites (the turtle and the octopus) together. Models are `@Observable` classes on the main actor, so SwiftUI views redraw when what they read changes.

The folders follow the layers: `App/` hosts SwiftUI in AppKit, `Shell/` is the controller of the whole app (with the `InputRouter`), the models are in `Stage/` (the bubbles), `MicroApps/`, and `Sprites/`, and the SwiftUI views are in `Views/` (each microapp's own views sit in its folder). `Animation/` and `Extensions/` hold what the rest shares.

- `Sources/Honu/App/main.swift`: starts `NSApplication` with `AppDelegate` as a regular app (Dock icon and menu bar).
- `Sources/Honu/App/AppDelegate.swift`: sets the Dock icon and the menu bar (Quit and the Edit commands, Undo and Redo among them, which text fields and web pages need), creates the `Shell` and the `FloatingWindow` covering the main screen's visible frame (everything but the menu bar and Dock), and starts the `FrameClock`, which calls `Shell.tick` and `ClickThrough.update` every frame and gives the window the shell's `isOnAllDesktops`. When Honu stops being the active app, it closes any popup and sends the window behind every other (`sendBack`); when Honu becomes active again, it brings the window to the front (`bringFront`). A local event monitor turns what SwiftUI's gestures do not cover into `InputEvent`s for the `InputRouter`, with whether the keyboard goes to a text field or a web page (`isTyping`), so type-ahead and ⌘Z leave those alone. It saves once more when Honu quits.
- `Sources/Honu/App/FloatingWindow.swift`: `FloatingWindow`, a transparent, borderless, shadowless window at the normal level, behind the other apps' windows while they are in use, that stays on the Space Honu was launched on, or shows on every Space (`isOnAllDesktops`); it is transient, so Mission Control and App Exposé hide it instead of laying it out over the other windows, and it never goes full screen, hosting `ShellView` in a `FirstClickHostingView`, an `NSHostingView` that does not resize the window to fit and whose first click acts rather than only bringing Honu forward. It can become key, which borderless windows refuse by default but text fields need. `ClickThrough` lets clicks through to the apps below except where `Shell.takesClick(at:)`; a window that ignores mouse events gets none, so it polls the global mouse position each frame to decide.
- `Sources/Honu/App/FrameClock.swift`: `FrameClock`, a `CADisplayLink` on the window that calls back once per frame of the display (60 or 120 times a second), in the common run loop mode so it keeps running while a drag or menu tracks. Everything that moves takes the time since the last frame, so the frame rate does not change how fast things go.
- `Sources/Honu/Shell/Shell.swift`: `Shell`, the controller of the whole app (what it gives the views is in `Shell+Views.swift`, and its `snapshot` and `restore` in `Shell+Saving.swift`): the `Registry` of microapps (and the `maker`, which the launcher's **+** starts), the `Stage`, the `Turtle`, the `Octopus` and the `Trash` it shows, and what the turtle has open (`popup`: the launcher, at its top level or in a folder, or the system menu with Show on All Desktops and Exit). What is under a point is one `Hit`, from the top layer down: an open popup (which takes every click, like a native menu), the turtle, the octopus, then the bubbles. Clicking the turtle hops it and opens the launcher there (`clickTurtle`; `rightClickTurtle` opens the system menu, where `toggleAllDesktops` shows Honu on every Space or only one); a `LauncherTile` starts a new item (`choose`): of a built-in microapp (`start`), of an installed microapp (`launch`), or a new microapp to describe, and the turtle spits out a bubble showing it (`spit`); or it is a folder (`LauncherFolder`; the one there is, the Reef, `.builtIn`, holds the built-in microapps), which opens in place of the launcher's top level (`open`, and `closeFolder` back). `launcherTiles` lists the tiles of the level open (`launcherTiles(in:)` any level's; a folder's tile shows a `preview` of the symbols of what it holds). `Shell.init` takes the `pages` built in (`BuiltinCatalog.shipped` unless given others) and registers a `BundledWebApp` for each, after the native microapps. Dragging a bubble from its rim resizes it instead of moving it (`dragBubble(_:from:by:velocity:pointer:)`, through `resizeBubble` and `endBubbleResize`), and `zoom` switches it between the size the user chose and its microapp's. Dragging a bubble more than `summonDistance` calls up the octopus; with the pointer within its reach the bubble shrinks, and letting go there swallows it. Dragging an installed microapp's tile does the same (`dragTile`, `endTileDrag`; built-in tiles wobble instead): dropped on the octopus, the tile goes down its mouth (`swallowedTile`) and the microapp is uninstalled (`uninstall`), the octopus swallowing it with every bubble of it in one gulp. An installed microapp's tile also has a right-click menu with Uninstall (`uninstall(_:from:)`, the tile going down the octopus's mouth from where it is, without asking, since it can be undone). `undoDelete` has the octopus spit the latest gulp in the trash back, putting an uninstalled microapp's tile back too. `tick` lets the microapps catch up (setting each bubble's breathing from `isBusy` and playing the motions they ask for), steps the stage by the time since the last tick (at most 1/30 s), deletes for good what the trash forgets (bubbles, and their items once no bubble shows them, and uninstalled microapps), and autosaves. The views read the models (the stage's bubbles, the sprites) but act only through the shell, and ask it what a bubble shows (`appearance`, `title`, `content`) and what the launcher lists (`launcherTiles`), so they never reach into the microapps.
- `Sources/Honu/Shell/InputRouter.swift`: `InputRouter` turns the input SwiftUI's gestures do not cover into calls on the shell: presses on content AppKit views take for themselves (to raise that bubble, while the press goes on), right-clicks on the turtle (opening the system menu; on the launcher, `launcherFrame`, they go on to its tiles' menus, even over the turtle; elsewhere they close any popup), Escape (leaving a folder of the launcher, or closing a popup), printable keys while no text field has the focus (type-ahead), and ⌘Z (undoing a delete, unless a text field has the focus). It takes `InputEvent`s rather than `NSEvent`s, so the rules are tested without AppKit. Everything else comes in through the views' gestures, and `ClickThrough` decides where clicks go.
- `Sources/Honu/MicroApps/`: the `MicroApp` protocol and one folder per microapp, the controller and its model apart from the views (and the view states, which belong to one bubble each).
- `Sources/Honu/MicroApps/MicroApp.swift`: the `MicroApp` protocol and what goes with it. A bubble's `ViewTarget` (`AppID` + `ItemID`) names one item, so a microapp can have any number of bubbles. `MicroApp` is three smaller protocols and a little more: `ItemStore`, what it keeps (its `items`, which it creates, removes, and saves and loads as JSON, keeping their ids; `ItemIDs.skip(past:)` keeps new ids after restored ones, and an `ItemTable` (`ItemTable.swift`) does all of this for a value per item, as every microapp uses it); `ItemLook`, how they look (`appearance`: glass tint, size, the smallest the user can resize it to, `minSize`, text color; `title`, the bubble label; `isBusy`, breathing); and `ItemViews`, the SwiftUI `content` of a bubble. It also has its `id`, its launcher tile's `launcherLabel` and `launcherSymbol`, and whether the launcher lists it (`isLaunchable`), and catches up on background work in `update`, where its `Context` gives it the time of the frame and it can ask for `Effect`s on the bubbles showing an item, such as a `Motion` for every one of them, or `resetSize`, dropping the size the user resized them to. Each bubble also owns a view state its microapp makes for it (`newViewState`), for what belongs to that one view rather than to the item, such as whether it still has to take the focus; its type is the microapp's `ViewState` (`NoViewState` if it keeps nothing), and `content` and `typeAhead` take it typed. The shell holds view states untyped, and goes through `anyContent` and `anyTypeAhead`, the one place they are cast. A view state that is `FocusTaking` takes type-ahead: text typed while no field has the focus goes to the newest bubble the turtle spat out (`Shell.type`), as long as its `focusPending`, and its microapp puts it in the field it shows first (`typeAhead`); when the field takes the focus, a view takes it once with `takesFocus`, and `placeCursorAtEnd` (both in `Views/Focus.swift`) keeps the text from being selected and typed over. `Registry.swift` holds the microapps in launcher order and routes a target to its microapp, and `shortLabel` (`ShortLabel.swift`) shortens titles. To add a microapp, give it a folder in `Sources/Honu/MicroApps/`, implement the protocol there, and list it in `Shell.init`.
- `Sources/Honu/MicroApps/Notes/`: the Notes microapp (`NotesApp.swift`; the view, `NoteEditor.swift`), any number of notes, each a `TextEditor` on yellow-tinted glass; a new note's bubble takes the focus when it appears. A note's title is its first line with text (`titleLine`), which labels its bubble (`shortLabel` keeps labels short); the editor sets it in `titleFont` (`NoteEditor.style`, on an `AttributedString` the view state keeps so the cursor stays, with the font the only attribute allowed), so the note's `appearance` asks for no title above it (`showsTitle`).
- `Sources/Honu/MicroApps/Ask/`: the Ask AI microapp, left off the launcher (asking Claude is to become feeding a bubble to the turtle) but keeping its chats (`AskApp.swift`; the model, `Chat.swift`; the view, `ChatView.swift`), any number of `Chat`s, each shown through a `ChatView` with a `FocusRequestState` (`Views/Focus.swift`, which Maker shares: whether to take the focus; a chat counts up `focusRequests` when the user has to type again, and each view takes the focus once per request). A chat asks for a question, then shows the answer as it streams in; the view measures its content (`contentHeight`), and the chat's `appearance` asks for a bubble that fits it, between `startHeight` and `maxHeight`, which the shell applies. `update` polls every chat's stream and turns how a question ended (`Outcome`) into a `rise` or `wobble`, and `isBusy` makes a chat's bubbles breathe while Claude works. A question still being answered when Honu quits is saved as interrupted.
- `Sources/Honu/Claude.swift`: asks Claude through the `ClaudeClient` protocol. A `ClaudeRequest` is a prompt, a system prompt, and an effort; Ask AI's system prompt is `Chat.systemPrompt`, and the Maker's is `MakerPrompt.system`. `ClaudeCode` runs the Claude Code CLI headless for each request (`claude -p`, the prompt on standard input, `arguments(for:)`: `stream-json` output with partial messages, `claude-opus-5-5` at the request's effort, no tools, no saved session), so Honu needs no API key: Claude Code signs in with the user's Claude account. It finds `claude` in `PATH` or the folders it is usually installed in (`executable`), since an app opened from the Finder has no shell `PATH`, runs it in `~/.honu/` (`workingDirectory`, created if missing) so no project's CLAUDE.md comes along, and leaves `ANTHROPIC_API_KEY` out of its environment. `EventParser` turns its JSON lines into `ClaudeEvent`s: the Messages API's text deltas passed on as `stream_event`s, and the closing `result`; `claude` exiting without one fails with what it wrote to standard error. Standard error is read alongside the answer, on a thread of its own, since a full pipe would stall `claude` mid-answer, and its exit is awaited through `terminationHandler` rather than a blocked thread; tests run `receive` on a stand-in shell script. Cancelling the stream terminates `claude`. Events go into an `AnswerStream`, a locked queue the main actor drains each frame (`take`), as the Rust version's channel did, so tests feed it by hand (`FakeClaude` in the tests).
- `Sources/Honu/Services.swift`: `Services`, what the microapps share: the `ClaudeClient`. `Shell.init` takes the services, so tests can pass a fake.
- `Sources/Honu/MicroApps/Web/`: the Web microapp (`WebApp.swift`, with `LoadEnd`; what a link shows, `PageSource.swift`; the views, `WebContent.swift` and `PageView.swift`), left off the launcher for now but keeping its pages, any number of pages. A new page asks for a link, then `PageView` shows it in a `WebPage` in SwiftUI's `WebView`; YouTube links (`youTubeID`, `PageSource`) play in YouTube's embedded player, loaded from an HTML page with a base URL, because the player refuses to play without a referring origin. `PageView` tells the microapp when it starts and stops loading (`startedLoading`, `stoppedLoading`), with how the load ended (`LoadEnd`), so a page's bubbles breathe while it loads, rise once it has, and wobble if it failed; a load given up (the bubble gone, or a new navigation replaced it) does neither. `LoadEnd` unwraps `WebPage.NavigationError` to tell the two apart. Only the first load counts, not following links.
- `Sources/Honu/MicroApps/Bundled/`: the microapps built into Honu as web pages, the Reef's after the native ones. `BuiltinCatalog` lists the folders of `Sources/Honu/BuiltinApps/` (copied into the resources; each `<name>/index.html` with any files beside it), skipping names that break the name rule (`isValidName`: lowercase letters, digits, and hyphens, starting with a letter, since the name is the host of the page's URL), as `BundledPage`s ordered by label, each with what its page says about itself (`PageMeta`, as the Maker reads it). A `BundledWebApp` (`AppID` `builtin.<name>`) runs one as the Maker runs an installed microapp, but never changes it: any number of instances, each saving its page's state in `builtin/<name>/instances/<uuid>.json` beside the store (`root(for:)`, as `MakerApp.root` does), served at `honu-builtin://<name>/` (`site`, `BuiltinCatalog.scheme`), apart from `honu-app://`; no change bar (`chrome`); its bubbles rise once the page loads, and wobble at its first error after each load. A page no longer shipped loses its bubbles on restore and keeps its data. The design is in `docs/BuiltinApps.md`. The first is `BuiltinApps/timer/`, a countdown Timer.
- `Sources/Honu/MicroApps/Maker/`: the Maker microapp (`MakerApp.swift`; the models, `GeneratedApp.swift` and `Instance.swift`; the views, `MakerView.swift` and `MicroappView.swift`), any number of microapps Claude writes (`apps`), each running in any number of `Instance`s, the items its bubbles show: an instance has its `GeneratedApp`, its own saved state (`dataID`, `dataURL`), and the size its page asked for, which a new page resets. A microapp is installed once its first page is written (`hasPage`; `library` lists the installed ones, which the launcher shows), and stays when its last instance is deleted; `launch` starts another instance of it, its page running at once. One never made goes to the Trash with its last bubble. Uninstalling goes through `withdraw` (out of the library while the octopus can still bring it back, and not saved, so quitting finishes it), then `reinstate` or `uninstall` (deleting it, its instances, and its folder). A new one asks for a description, then Claude writes a page that does it (`MakerPrompt`: one self-contained HTML file that fills whatever size its bubble is resized to, at medium effort), which `WritingPreview` shows streaming in; `AppSource` finds the page in the answer (Claude may wrap it in a Markdown fence, and it starts a line of its own, so tags named in the text before it are not taken for it; a page cut off is no page) and reads what it says about itself in its head (`PageMeta`: its `<title>`, the size it wants in `honu-size`, and its launcher tile's SF Symbol in `honu-symbol`). The page then runs in the bubble, which starts at its size, with a `ChangeBar` below for asking Claude to change it (its field, sent with Return or its Go button; the draft is cleared once a page is made or changed), fixing the errors it reported, and undoing the last change; all of these change the microapp, so every instance of it loads the new page, and the draft is shared. A `GeneratedApp` goes from `describing` to `writing` (`making`, `changing`, or `fixing`) to `running`; a page that fails to come back leaves the page before it running with a `notice`, or, without one, asks for the description again. Errors the page reports within `fixWindow` of loading are fixed once without asking, a second after the first (`fixDelay`), unless the page is itself a fix; later ones wait for the user. The bubbles of every instance rise once a new page loads (`loaded`) and wobble when writing fails; a description's bubbles drop the size the user gave them once its first page is written. Each microapp is a folder of its own (`AppFolder`, named by a UUID, not the item id, which restarts with a new store) under `~/.honu/microapps/`, or `<name>.microapps/` beside the file `HONU_STORE` names (`MakerApp.root`), holding its page (`index.html`), what each instance saves (`instances/<uuid>.json`), and the pages before each change (`history/`). The store keeps each microapp's folder, description, and draft, and each instance's microapp, data file, and size (`{ apps, instances }`). Loading moves to the Trash the folders no microapp has, and deletes the data files no instance has. `MicroappView` (in `MicroApps/Pages/`, with `MicroappScheme` and `Bridge`, which pages built in share) runs the page in a `WebPage` served by `MicroappScheme` at `honu-app://<folder>/`, so each has an origin of its own, a secure context, and relative links (the scheme never serves outside the folder, nor anything in `instances/`, compared without case, so a page reaches only its own data), and loads it again for each new `version`, telling its `PageHost` (the Maker, or a `BundledWebApp`) when it loads, what errors it reports, and what size it asks for; `StaysHome` keeps the page from navigating away, opening links in the browser instead. `Bridge` gives the page `window.honu`: `load` and `save` (its state, in its instance's file), `fetch` (http and https through `URLSession`, past CORS), and `resize` (which the bubble ignores once the user has resized it, unless zoomed), and hears of its errors (`error`, `unhandledrejection`, `console.error`).
- `Sources/Honu/Stage/Bubble.swift`: `Bubble`, the view model of one bubble: its target, center, velocity, its size (`size`: the size the user resized it to, `userSize`, unless it has none or is zoomed back to the size its microapp asks for, `microappSize`, with `isZoomed`), and whether doomed or swallowed. `rimEdges(at:)` tells which edges dragging from a point resizes: the rim is the glass around the content (`rimWidth`, thinner along the title, `topRimWidth`), and corners resize both ways (`cornerReach`). There is one kind of bubble: it shows its item under its title, and never closes into an icon. Its outline is a continuous-corner rounded rectangle (`cornerRadius`; `drawnFrame` is where it is drawn this frame), and `contains` hit-tests that outline as drawn, so presses past its rounded corners go to whatever is below. Bubbles show what they are doing through motion: `isBusy` makes one breathe (only the glass swells, `swell`, so content and hit-testing hold still), and `play` runs a short `Motion` that moves the whole bubble and returns it: `rise` when a task finishes, `wobble` when the user is needed. A bubble flying out of the turtle, back from the octopus, or into it follows a `Flight` of its own instead of the physics or the pointer: `fly` pops it out small and grows it (with a little overshoot) on the way, and `swallow` shrinks it into the octopus's mouth. `animate` advances the flight each frame; `destination` is where it will rest. A bubble is also soft: `wobble`, which `Stage.step` calls after the physics, feels changes in how where it is drawn moves (bounces, drags, pushes, its motions; smoothed in `pace`, which starts as it is first found), a fast pace, landing from a flight (which splats it), other bubbles pushing it (`knock`, felt more than it moves it, and `press`, which flattens it against the pusher's edge), and flying out of the turtle (its path softened, and its growing), and while something sets it wobbling it keeps a `Jelly` and publishes its `outline` (none at rest) and the `contentTransform` its content takes (the identity at rest), dropping the jelly once it settles, or at once when it is resized, flying into the octopus, swallowed, or changes size. Hit-testing stays with the bubble at rest; `drawnOutline(grownBy:)` and `drawnBounds` are where the wobbling glass is drawn.
- `Sources/Honu/Stage/Stage.swift`: `Stage`, every bubble in back-to-front paint order. The stage hit-tests, raises, drags (the dragged bubble stays on top, takes the pointer's velocity so it glides when let go, and new bubbles go below it), resizes them (`startResize`, `resized`, `endResize`: the `Edges` being moved go with the pointer while the opposite ones stay put, within the bubble's `minSize` and the screen; the bubble being resized is held, as a dragged one is) and zooms them between the user's size and the microapp's (`zoom`; `setUserSize` puts back a saved size, fitted to the screen), spits out new ones (`spit`: it flies out of the turtle's mouth, stepping aside from a bubble already there, as windows cascade), and sends them into the octopus and back. `step` advances the flights, runs the physics, then wobbles the bubbles. Swallowed bubbles stay on the stage, out of sight, until the trash forgets them. It knows nothing of what a bubble shows.
- `Sources/Honu/Stage/Trash.swift`: `Trash`, what was deleted recently enough to be brought back. Each gulp (`Swallowed`) is bubbles, each with where it was (`Morsel`), and the microapp uninstalled with them, if any. It keeps them for `undoSeconds` after the last gulp; clicking the octopus or its hint, or ⌘Z, spits the latest gulp back (`spitBack`, which leaves time for the one before it), and `forget` hands over what is too old to bring back, deleted for good.
- `Sources/Honu/Stage/Jelly.swift`: `Jelly`, a bubble's outline as a soft ring of points around its center that lags behind the bubble, as cartoon jelly: changes in the bubble's velocity kick it (`feel`, squashing it against where it is flung, the kicks of the last moments adding up toward `kickLimit` ever more slowly), it stretches along a fast velocity (`stretching`), stiff springs keep it off the screen edges and softer ones off the edges of bubbles pushing it (`Contact`), `splat` flattens and widens it, `inflate` swells or draws it in, and shape matching (toward the area-keeping part of the best-fit linear map, `fit`, without its rotation, `withoutRotation`, so it never turns) with a bending force springs it back, round-cornered, after a few wobbles (`isSettled`). `contentTransform` is the best-fit map, exaggerated a little, which the content takes, kept by `limited` within `contentStretch` along each main direction and finite, since AppKit views abort on a transform that is not finite and SwiftUI inverts it for nested views; `outline(margin:)` is the ring pushed out wherever it would leave the content uncovered, so the rim stays. Content is limited to linear maps because SwiftUI's shaders cannot draw AppKit views; `docs/Jelly.md` records the experiments behind this.
- `Sources/Honu/Stage/Physics.swift`: per-frame motion. Released bubbles keep the pointer's velocity and slow down with friction until they stop (`restSpeed`), a bubble left alone stays where it is put, crowded bubbles push each other apart with a damped soft collision that passes momentum on (partial overlaps are allowed so the glass stays visible), and bubbles bounce off the screen edges. Collisions take a bubble as a rectangle with rounded corners (`separation`), and bigger bubbles are heavier; bubbles in flight or swallowed are left out. It writes a bubble's center and velocity only when they change, so still bubbles cause no redraw.
- `Sources/Honu/Persistence.swift`: `SavedState`, what is kept for the next launch: the turtle's place, whether Honu shows on all desktops, which bubbles show which items, where (relative to the screen center), and the size the user gave each, if any, and whether it is zoomed (fitted to the screen on restore), plus each microapp's own JSON. The shell makes it (`Shell.snapshot`, saving where a bubble will rest, so one saved mid-flight comes back where it lands) and puts it back when it starts (`Shell.restore`, without the focus, deleting items no bubble showed, such as one still in the octopus). `Autosave` knows nothing of the shell: it decides when and where to write a `SavedState`, and reads it back (`restore`; a store it cannot read is moved aside to `unreadableURL`, `state.unreadable.json`, rather than written over). It checks once a second and writes only what changed; bubbles gliding or pushed aside are not a change, but a bubble dragged somewhere is (`moved`). It sorts the keys of each microapp's JSON (`canonical`), since `JSONEncoder` may order them differently from one call to the next.
- `Sources/Honu/Sprites/Sprite.swift`: `PixelGrid`, a character-grid sprite (one character per pixel, `spritePixel` points square), painted by `SpriteCanvas` as crisp squares; `PixelMask` makes hit-testing skip transparent pixels. Sprite animations run on the `now()` clock.
- `Sources/Honu/Animation/`: how things move over time: `Motion` (a bubble's `rise` and `wobble`), `Flight` (a bubble's trip out of the turtle or into the octopus, which a tile dropped on the octopus follows too; `after` gives it some time after it started), the easing curves flights follow, and the `now()` clock that animations, the frame tick, the octopus's memory, and autosave run on.
- `Sources/Honu/Extensions/`: what Honu adds to system types, one file per type and purpose (`CGPoint+Arithmetic.swift`, `CGSize+Arithmetic.swift`, `CGRect+Points.swift`, `Color+RGB.swift`, `Color+Error.swift`).
- `Sources/Honu/Sprites/Turtle.swift`: the turtle, which starts in the bottom-left corner and can be dragged anywhere on screen. It bobs while idle, hops when clicked, and briefly opens its mouth (`spit`) for each bubble.
- `Sources/Honu/Sprites/Octopus.swift`: the octopus. It rises from the bottom edge, in the corner away from the turtle, while summoned or while something swallowed can still come back, and sinks again afterwards. While summoned, a comic speech bubble (`SpeechBubble`, in `SpriteViews.swift`) beside it offers to recycle the dragged bubble or uninstall the dragged tile's microapp (`offersHelp`, `offer`). Whether the *pointer* is within `reach` decides a drop, not where the bubble is. What it has swallowed is kept in the `Trash`, which it only shows: it stays up while the trash can undo, showing "Click to undo", gulps as things go down, and `spit`s when the shell takes one back (`riseOrSink` after the trash changes).
- `Sources/Honu/Views/`: the SwiftUI views. `ShellView` stacks the bubbles, the octopus, the turtle, the open popup (over a nearly transparent layer, so a press outside closes it), and a tile dragged out of the launcher or going down the octopus, in the `stage` coordinate space. `StageView` (`StageView.swift`) draws the bubbles back to front, so the one pressed last (the stage's top) covers the others. They share one `GlassEffectContainer` (without one, Liquid Glass renders untinted), whose spacing is 0 so bubbles never blend; and since the container merges glass shapes that touch and draws all glass beneath all content, each bubble's glass and content are cut away (`StageView.cuts`, `Cut`, and `CutAway`, all in `StageView.swift`) wherever a bubble above it lies, with a `gap`, so the one on top covers the others completely, however see-through its glass; a wobbling bubble's cut follows its outline, a smooth curve through its ring (`Path(smoothlyClosedThrough:)`). `CutAway` fits the outline and the cuts to the rectangle it is drawn in, since Liquid Glass hands a shape one already scaled while the bubble is drawn scaled. A `GlassEffectContainer` draws its glass above the other views in it, so `glassEffect` must go on the view whose content sits on the glass, never on a separate background layer, or the glass covers the content. Liquid Glass adapts to what is behind the window, so it looks gray in a capture over dark windows; compare renderings against the same backdrop. `BubbleView` draws a bubble as interactive Liquid Glass (whose shape swells while breathing, and follows the bubble's outline while it wobbles, its content taking the bubble's `contentTransform`) with its title over its microapp's content; dragging moves it, or resizes it from the rim, where the pointer takes the system's resize cursor (`pointerStyle`), and double-clicking the title zooms it. A bubble's content sits in an `UndoScope` (`UndoScope.swift`), an AppKit view in the responder chain with the bubble's own undo history (`Shell.undoManager(for:)`), since the window has one for all bubbles, SwiftUI's `undoManager` cannot be set, and its text views keep the first one they find; it also undoes for web pages, which leave Undo to the next responder. `TurtleView` and `OctopusView` (`SpriteViews.swift`) animate the sprites with `TimelineView`; the octopus's pauses while it is out of sight. `LauncherView` is the turtle's launcher, a glass panel of tiles, four to a row, which grows with its tiles and scrolls past three rows (`size(for:header:)`, kept on screen by `menuCorner`): the Reef, the installed microapps, and New Microapp (**+**), or, in a folder, its tiles under a `FolderHeader` with a back button; a folder's tile draws its `FolderPreview`; a tile (`TileView`, showing a `TileFace`) is clicked to start what it starts, and dragged (an installed microapp's) or wobbled (the others); an installed microapp's tile has a `contextMenu` with Uninstall. `SystemMenu` (`Menus.swift`) is the right-click menu with Show on All Desktops (checked while on) and Exit, made of `MenuItem`s.
- `Tests/HonuTests/`: Swift Testing tests (`@Test`, `#expect`), run on the main actor and importing the executable target with `@testable import Honu`. They drive the models and controllers directly, not the views: what depends on time takes the time as an argument (the trash's `swallow`, `spitBack`, and `forget`, the turtle's `hop` and `spit`, the Maker's `loaded` and `report` (and a `Context` takes the time, which the shell's `tick` passes down through `Registry.update`), autosave's `tick` and `save`, and the shell's `uninstall`, `endTileDrag`, and `undoDelete`, default to `now()`), and a `Shell` can save to a store of its own (`storeURL`), so persistence is tested against a temporary file. `makeShell` builds one with no pages built in unless given some (`writePages` and `page` in `BundledTests.swift` write them to a temporary folder), so tests do not depend on what Honu ships; `BundledTests` also checks every page Honu ships.

## Conventions

- The PRDs in `docs/` are the design to follow: `docs/UI.md` for the UI's principles and behavior, `docs/Launcher.md` for the launcher, `docs/BuiltinApps.md` for its folder of built-in microapps, native and web, `docs/Resizing.md` for resizing bubbles, `docs/Jelly.md` for bubbles that wobble like jelly, `docs/Connectors.md` (a draft) for reading the user's services through their Claude connectors, and `docs/microapps/` for each built-in microapp (`Note.md`, `WebPage.md`). Read the relevant one before changing what it covers, keep changes to it, and update it in the same change when the design itself changes. A new design that takes more than a few sentences gets a PRD of its own in `docs/`.
- Everything in the repository must be in English: identifiers, comments, UI strings, docs, and commit messages — even when the conversation is in Chinese.
- After changing Swift code, run `swift build`, `swift test`, and `swift format lint --strict -r Sources Tests Package.swift` before reporting the work as done, and fix any warnings they raise.
- Honu asks Claude through the user's Claude Code login and uses no API key. `.env` and `.env.*` stay git-ignored so an old key file is never committed; never read, print, or commit one, and never put a key anywhere in the repository.
