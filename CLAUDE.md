# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Honu is a native desktop GUI app written in Rust (edition 2024) using **eframe/egui 0.37** — an experiment in desktop GUI design that departs from Windows/macOS conventions. It currently renders draggable, window-like bubbles (some opaque, some translucent glass) that float directly on the real macOS desktop, above all other windows. Only the turtle's place persists across launches, through eframe's `persistence` feature (`~/Library/Application Support/Honu/app.ron` on macOS; delete it to reset); everything else is in-memory.

## Commands

```sh
cargo run                    # build and launch; bubbles float on the real desktop (quit with ⌘Q)
cargo run -- --windowed      # launch in an ordinary window with its own wallpaper instead
cargo build --release        # optimized build
cargo clippy --all-targets   # lint
cargo fmt                    # format (cargo fmt --check to verify)
cargo test                   # run tests (physics simulations in src/physics.rs)
cargo test <name>            # run a single test by name filter
trunk serve                  # build the web version and serve it at http://127.0.0.1:8080 with live reload
trunk build --release        # optimized web build into dist/
cargo clippy --target wasm32-unknown-unknown   # lint the web build too
```

CI (`.github/workflows/ci.yml`) runs the format check, both clippy builds (warnings are errors), and the tests on Linux for every push, and clippy and the tests on macOS for pull requests only. In Claude Code cloud sessions, `.claude/hooks/session-start.sh` installs clippy, rustfmt, and the wasm target and fetches the crates.

The web version needs `rustup target add wasm32-unknown-unknown` and [trunk](https://trunkrs.dev). It is the `--windowed` experience in a browser: it cannot float on the desktop, and the turtle's menu has no Exit there, since quitting means nothing in a page. Web-only files live in `web/` (the page is `web/index.html`, whose asset paths are relative to `web/`); `Trunk.toml` at the root points trunk there and writes the build to `dist/`.

## Architecture

- `src/main.rs`: there are two `main()`s, picked by `target_arch`. The web one (`wasm32`) starts `HonuApp` in the `<canvas id="honu">` of `web/index.html` through `eframe::WebRunner`, never floating; keep platform-specific code behind `cfg` so both targets build. The native `main()` configures the window (`NativeOptions` / `ViewportBuilder`): by default transparent, borderless, and always on top, maximized after the first frame to cover the screen except the menu bar and Dock; with `--windowed`, an ordinary window that paints its own wallpaper. The window and Dock icon is `assets/icon.png`, embedded at compile time and rendered at 512×512 from its source `assets/icon.svg` (the README illustration lives separately in `docs/images/`). It then starts the event loop with `eframe::run_native`, constructing it with `HonuApp::new`. `HonuApp` holds all state, with the bubbles in a `Stage`. The app starts with only the turtle on screen; every bubble comes from its menu. `impl eframe::App for HonuApp` allocates one full-window painter, handles drag, double-click, and hit-testing on it, then paints each bubble followed by its content (if open), so content stacks correctly, and paints the octopus and then the turtle last, above everything. `save` and the end of each turtle drag store the turtle's offset from the window center, under separate keys for floating and `--windowed`; the drag-end save matters because quitting with ⌘Q or from the Dock exits without calling `save`. Window and egui-memory persistence are turned off. Clicking the turtle with either button (or tapping it) opens `TurtleMenu` where the pointer is, a foreground `egui::Area` with one item per microapp (`menu_label`: Add Note, Ask AI) and (desktop only) Exit; a microapp's item starts a new item there (`HonuApp::start`), and the turtle spits out a bubble showing it that opens on landing (`Stage::spit_panel`), stepping aside from any panel already there; while it is open the floating window takes every click, and a press outside it or Escape closes it (a press on the turtle sets `menu_dismissed`, so its click does not reopen the menu). Only the top bubble's content takes input, so bubbles lying over another's content can still be grabbed.
- `src/stage.rs`: `Stage`, the bubbles in back-to-front paint order (pressing on a bubble moves it to the top), and how they are hit-tested, dragged (the dragged bubble is always the top one, and new bubbles go below it), opened, spat out with cascading panels (`spit_panel`), and stepped (`step` animates them and runs the physics). It knows nothing of what a bubble shows.
- `src/desktop.rs`: reads the global mouse position (CoreGraphics on macOS). While floating, the window lets mouse events through (`ViewportCommand::MousePassthrough`) except when the mouse is on a bubble, the turtle, or the octopus; since a pass-through window gets no pointer events, this global position is polled every frame to decide.
- `src/bubble.rs`: `Bubble` and its outline `Shape`, a rounded rectangle with superellipse corners and a lit rim. A closed bubble is a rounded square like a macOS app icon; double-clicking toggles `open`, and the bubble then morphs (with a small overshoot) into a larger panel that shows its `Content`. Bubbles show what they are doing through motion: `set_busy` makes one breathe (only the drawn outline, `display_shape`, swells, so content and hit-testing hold still), and `play` runs a short `Gesture` that moves the whole bubble and returns it: `Rise` when a task finishes, `Wobble` when the user is needed. A new bubble comes out of the turtle's mouth small and grows (`scale()`) as it flies to its place along its own path (`spawn_from`). `shrink` scales the whole outline, for a bubble held over the octopus or swallowed by it; content shows only at full size.
- `src/physics.rs`: per-frame motion, stepped from `ui()` before painting. Released bubbles keep the pointer's velocity and slow down with friction, idle bubbles drift with a slow per-bubble float, crowded bubbles push each other apart with a damped soft collision that passes momentum on (partial overlaps are allowed so the glass stays visible), and bubbles bounce off the window edges. Open bubbles can be thrown but neither float nor push, and spawning bubbles are left out of the simulation until they land. The app repaints continuously.
- `src/turtle.rs`: the pixel-art sea turtle, which starts in the bottom-left corner and can be dragged anywhere inside the window, drawn from a character-grid sprite as one mesh of square pixels. It bobs while idle, hops when clicked, and briefly opens its mouth (`spit`) for each bubble; hit-testing ignores its transparent pixels.
- `src/octopus.rs`: the pixel-art octopus that deletes bubbles, drawn like the turtle. It rises from the bottom edge, in the corner away from the turtle, only once a bubble has been dragged `SUMMON_DISTANCE` away from where it was picked up, and sinks again afterwards, so it never sits on the desktop. Whether the *pointer* is within `REACH` decides a drop, not where the bubble lands, so a throw never deletes anything; a bubble held there shrinks (`Bubble::set_doomed`) and one dropped there is swallowed (`swallow_into`). Swallowed bubbles stay in its stomach for `UNDO_SECONDS`, while it shows "Click to undo"; clicking it or the hint (which `contains` counts as part of it) or ⌘Z (unless a text field has focus) spits the latest one back to where it was picked up (`Bubble::spit_back`). After that `update` returns them, and an item no other bubble shows is removed from its microapp, which also cancels a chat's stream. Like the turtle it is painted above all bubbles and hit-tested before them.
- `src/claude.rs`: asks Claude a question through the Messages API over raw HTTP (`ehttp`, which streams both natively and in the browser; there is no official Rust SDK), parsing the server-sent events into `Event`s on a channel. Uses `claude-opus-5-5` at low effort with `fallbacks: "default"`; the web build adds the `anthropic-dangerous-direct-browser-access` header that browsers need. A 401 comes back as `KeyRejected`.
- `src/microapp.rs`: the `MicroApp` trait. Microapps keep their own data (the model) and logic; a `Bubble` is only a view of one item of one microapp, pointing at it with a `ViewTarget` (`AppId` + `ItemId`), so a microapp can have any number of bubbles. An item is deleted (`remove`) once the octopus forgets the last bubble showing it. A microapp works through a `Context`, which carries the shared services (the API key) and collects `Effect`s it asks of its bubbles, such as a `Gesture` for every bubble showing an item; `View` says where and how an item's content is drawn. `Registry` holds the microapps (in menu order) and routes each `ViewTarget` to its microapp; adding a microapp means implementing the trait in `src/apps/` and listing it in `HonuApp::new`.
- `src/apps/notes.rs`: the Notes microapp, any number of notes, each a multiline text field that takes the focus when a new note first opens. A note's bubble is labeled with its first line with text (`bubble::short_label` keeps labels short).
- `src/apps/ask.rs`: the Ask AI microapp, any number of `Chat`s; the turtle spits out a new one from its menu. A chat asks for an API key if there is none, then for a question, then shows the answer as it streams in, reporting the height that fits so the panel (`Bubble::set_panel_height`) grows with the answer. `AskApp::update` polls every chat's stream and turns how a question ended (`Outcome`) into a gesture effect, and `is_busy` drives the breathing. `HonuApp::api_key` comes from `ANTHROPIC_API_KEY` (loaded from `.env` by `dotenvy`) on the desktop, where a pasted key is kept only in memory; on the web a pasted key is kept in local storage, and a key the API refuses is cleared.
- `src/render.rs`: all custom drawing. Bubbles are vertex-colored meshes of nested rounded-rectangle outlines with superellipse (continuous-curvature) corners shaded on the CPU by a small lighting model (diffuse/specular, Fresnel rim for glass); there are no custom shaders, so true background blur/refraction is not implemented (planned in `TODO.md`).

egui is **immediate mode**: `ui()` runs every frame and rebuilds the whole interface from the current state, so UI changes are made by mutating `HonuApp` fields, not by holding widget handles.

Note that egui 0.37's `App` trait uses `fn ui(&mut self, ui: &mut egui::Ui, frame: &mut eframe::Frame)`; older egui examples online use `fn update(&mut self, ctx: &egui::Context, ...)` and won't compile as-is.

## Conventions

- Everything in the repository must be in English: identifiers, comments, UI strings, docs, and commit messages — even when the conversation is in Chinese.
- After changing Rust code, run `cargo clippy --all-targets` and `cargo fmt --check` before reporting the work as done, and fix any warnings they raise.
- The Claude API key lives in `.env` at the repository root as `ANTHROPIC_API_KEY` (the name the Anthropic SDKs read). `.env` and `.env.*` are git-ignored; only the empty template `.env.example` is committed. Never read, print, or commit `.env`, and never put a key anywhere else in the repository.
