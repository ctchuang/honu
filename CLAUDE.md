# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Honu is a macOS app written in Swift 6 with **SwiftUI** (hosted in AppKit) — an experiment in desktop GUI design that departs from macOS conventions. Liquid Glass bubbles float directly on the real desktop, above all other windows. It starts with only a pixel-art turtle in the bottom-left corner; clicking it opens a menu whose items make it spit out bubbles (a note, a question for Claude whose answer streams in, or a web page that can also play YouTube videos), and dragging a bubble calls up a pixel-art octopus that deletes it if dropped on. It needs macOS 26 or newer, for Liquid Glass (`glassEffect`) and SwiftUI's `WebView`. The turtle's place, the bubbles, and their items persist across launches in `~/Library/Application Support/Honu/state.json` (delete it to reset), or in the file `HONU_STORE` names, so a development run can keep bubbles of its own.

Honu was first written in Rust with egui; that version is in the git history before the switch to Swift.

## Commands

```sh
swift build                  # build
swift run                    # build and launch; bubbles float on the real desktop (quit with ⌘Q)
HONU_STORE=/tmp/honu.json swift run   # same, saving to a store of its own
swift build -c release       # optimized build
swift test                   # run the tests in Tests/HonuTests
swift test --filter <name>   # run tests whose name matches
swift format lint --strict -r Sources Tests Package.swift   # lint (as CI does)
swift format -i -r Sources Tests Package.swift     # format
```

CI (`.github/workflows/ci.yml`) runs on a `macos-26` runner for every push to `main` and every pull request: the strict format check (`swift format lint --strict`, so warnings fail), a debug build, the tests, and a release build.

`.swift-format` sets 4-space indentation and 100-column lines. The project is a Swift package, so it builds with the Command Line Tools alone; Xcode is not needed. The Command Line Tools do not ship SwiftUI's macro plugins, so **`@State` and other SwiftUI macros do not compile**: spell state out as a stored `State` value instead (`private let player = State(initialValue: Player())`, read through `wrappedValue`), or keep it in an `@Observable` model (Observation's macros do ship). With the Command Line Tools alone, SwiftPM sometimes fails to hand the compiler Swift Testing's macro plugin, and `swift test` fails with "plugin for module 'TestingMacros' not found"; pass it by hand: `swift test -Xswiftc -plugin-path -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing`. `swift run` launches a bare executable, not an app bundle; the Dock icon is set at launch from `Sources/Honu/Resources/icon.png`.

## Architecture

The code follows MVC. Each **microapp** (Notes, Ask AI, Web) is a controller that keeps its own model: any number of items, such as notes. A **bubble** is only a view of one item, pointing at it by id. The **shell** wires microapps, the stage of bubbles, and the two sprites (the turtle and the octopus) together. Models are `@Observable` classes on the main actor, so SwiftUI views redraw when what they read changes.

The folders follow the layers: `App/` hosts SwiftUI in AppKit, `Shell.swift` is the controller of the whole app, the models are in `Stage/` (the bubbles), `MicroApps/`, and `Sprites/`, and the SwiftUI views are in `Views/` (each microapp's own views sit in its folder). `Animation/` and `Extensions/` hold what the rest shares.

- `Sources/Honu/App/main.swift`: starts `NSApplication` with `AppDelegate` as a regular app (Dock icon and menu bar).
- `Sources/Honu/App/AppDelegate.swift`: sets the Dock icon and the menu bar (Quit and the Edit commands, which text fields need), creates the `Shell` and the `FloatingWindow` covering the main screen's visible frame (everything but the menu bar and Dock), and starts the `FrameClock`, which calls `Shell.tick` and `ClickThrough.update` every frame. A local event monitor hands the shell what SwiftUI's gestures do not cover: presses on content AppKit views take for themselves (to raise that bubble), right-clicks on the turtle (opening its menu), Escape (closing it), printable keys while no text field is first responder (type-ahead), and ⌘Z (undoing a delete, unless a text field is first responder). It saves once more when Honu quits.
- `Sources/Honu/App/FloatingWindow.swift`: `FloatingWindow`, a transparent, borderless, shadowless window at the floating level that stays on the Space Honu was launched on, hosting `ShellView` in an `NSHostingView` that does not resize the window to fit. It can become key, which borderless windows refuse by default but text fields need. `ClickThrough` lets clicks through to the apps below except where `Shell.takesClick(at:)`; a window that ignores mouse events gets none, so it polls the global mouse position each frame to decide.
- `Sources/Honu/App/FrameClock.swift`: `FrameClock`, a `CADisplayLink` on the window that calls back once per frame of the display (60 or 120 times a second), in the common run loop mode so it keeps running while a drag or menu tracks. Everything that moves takes the time since the last frame, so the frame rate does not change how fast things go.
- `Sources/Honu/Shell.swift`: `Shell`, the controller of the whole app: the `Registry` of microapps, the `Stage`, the `Turtle`, the `Octopus`, and where the turtle's menu is open. What is under a point is one `Hit`, from the top layer down: the open menu (which takes every click, like a native menu), the turtle, the octopus, then the bubbles. Clicking the turtle hops it and opens the menu there; a menu item starts a new item in its microapp (`start`), and the turtle spits out a bubble showing it. Dragging a bubble more than `summonDistance` calls up the octopus; with the pointer within its reach the bubble shrinks, and letting go there swallows it. `undoDelete` has the octopus spit the latest one back. `tick` lets the microapps catch up (setting each bubble's breathing from `isBusy` and playing the motions they ask for), steps the stage by the time since the last tick (at most 1/30 s), deletes for good the bubbles the octopus forgets (and their items, once no bubble shows them), and autosaves. The views read the models (the stage's bubbles, the sprites) but act only through the shell, and ask it what a bubble shows (`appearance`, `title`, `content`) and what the menu lists (`menuChoices`), so they never reach into the microapps.
- `Sources/Honu/MicroApps/`: the `MicroApp` protocol and one folder per microapp, the controller and its model apart from the views (and the view states, which belong to one bubble each).
- `Sources/Honu/MicroApps/MicroApp.swift`: the `MicroApp` protocol and what goes with it. A bubble's `ViewTarget` (`AppID` + `ItemID`) names one item, so a microapp can have any number of bubbles. A microapp gives its items' `appearance` (glass tint, symbol, sizes, text color), `title` (the bubble label), `isBusy` (breathing), and the SwiftUI `content` of an open bubble, and catches up on background work in `update`, where it can ask, through its `Context`, for `Effect`s on the bubbles showing an item, such as a `Motion` for every one of them. Each bubble also owns a view state its microapp makes for it (`newViewState`), for what belongs to that one view rather than to the item, such as whether it still has to take the focus. A view state that is `FocusTaking` takes type-ahead: text typed while no field has the focus goes to the newest bubble the turtle spat out (`Shell.type`), as long as its `focusPending`, and its microapp puts it in the field it shows first (`typeAhead`); when the field takes the focus, `placeCursorAtEnd` keeps the text from being selected and typed over. A microapp lists its `items` and saves and loads them as JSON, keeping their ids (`ItemIDs.skip(past:)` keeps new ids after restored ones). To add a microapp, give it a folder in `Sources/Honu/MicroApps/`, implement the protocol there, and list it in `Shell.init`.
- `Sources/Honu/MicroApps/Notes/`: the Notes microapp (`NotesApp.swift`; the view, `NoteEditor.swift`), any number of notes, each a `TextEditor` on yellow-tinted glass; a new note's bubble takes the focus when it opens. A note's bubble is labeled with its first line with text (`shortLabel` keeps labels short).
- `Sources/Honu/MicroApps/Ask/`: the Ask AI microapp (`AskApp.swift`; the model, `Chat.swift`; the view, `ChatView.swift`), any number of `Chat`s, each shown through a `ChatView` with a `ChatViewState` (the key draft, and whether to take the focus: a chat counts up `focusRequests` when the user has to type again, and each view takes the focus once per request). A chat asks for an API key if there is none, then for a question, then shows the answer as it streams in; the view measures its content (`contentHeight`), and the chat's `appearance` asks for a panel that fits it, between `startHeight` and `maxHeight`, which the shell applies. `update` polls every chat's stream and turns how a question ended (`Outcome`) into a `rise` or `wobble`, a refused key is forgotten so a new one can be pasted, and `isBusy` makes a chat's bubbles breathe while Claude works. A question still being answered when Honu quits is saved as interrupted.
- `Sources/Honu/Claude.swift`: asks Claude through the `ClaudeClient` protocol. `MessagesAPI` posts to the Messages API over URLSession (there is no official Swift SDK) with `claude-opus-5-5` at low effort and `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`), and `EventParser` turns the server-sent events into `ClaudeEvent`s; a 401 comes back as `keyRejected`. Events go into an `AnswerStream`, a locked queue the main actor drains each frame (`take`), as the Rust version's channel did, so tests feed it by hand (`FakeClaude` in the tests).
- `Sources/Honu/Services.swift`: `Services`, what the microapps share: the `ApiKey` and the `ClaudeClient`. The key comes from `ANTHROPIC_API_KEY` in the environment or in the nearest `.env` file in or above the working directory (Honu reads it at launch, so `swift run` from the repository picks it up); a key pasted into an Ask bubble is kept only in memory. `Shell.init` takes the services, so tests can pass a fake.
- `Sources/Honu/MicroApps/Web/`: the Web microapp (`WebApp.swift`, with `LoadEnd`; what a link shows, `PageSource.swift`; the views, `WebContent.swift` and `PageView.swift`), any number of pages. A new page asks for a link, then `PageView` shows it in a `WebPage` in SwiftUI's `WebView`; YouTube links (`youTubeID`, `PageSource`) play in YouTube's embedded player, loaded from an HTML page with a base URL, because the player refuses to play without a referring origin. `PageView` tells the microapp when it starts and stops loading (`startedLoading`, `stoppedLoading`), with how the load ended (`LoadEnd`), so a page's bubbles breathe while it loads, rise once it has, and wobble if it failed; a load given up (the bubble closed, or a new navigation replaced it) does neither. `LoadEnd` unwraps `WebPage.NavigationError` to tell the two apart. Only the first load counts, not following links.
- `Sources/Honu/Stage/Bubble.swift`: `Bubble`, the view model of one bubble: its target, center, velocity, float `phase`, whether open, and whether doomed or swallowed. Its outline is a continuous-corner rounded rectangle (`cornerRadius`; `drawnFrame` is where it is drawn this frame), and `contains` hit-tests that outline as drawn, so presses past its rounded corners go to whatever is below. Bubbles show what they are doing through motion: `isBusy` makes one breathe (only the glass swells, `swell`, so content and hit-testing hold still), and `play` runs a short `Motion` that moves the whole bubble and returns it: `rise` when a task finishes, `wobble` when the user is needed. A bubble flying out of the turtle, back from the octopus, or into it follows a `Flight` of its own instead of the physics or the pointer: `fly` pops it out small and grows it (with a little overshoot) on the way, opening it on landing if asked, and `swallow` shrinks it into the octopus's mouth. `animate` advances the flight each frame; `destination` is where it will rest.
- `Sources/Honu/Stage/Stage.swift`: `Stage`, every bubble in back-to-front paint order. The stage hit-tests, raises, drags (the dragged bubble stays on top, takes the pointer's velocity so it glides when let go, and new bubbles go below it), opens and closes bubbles with a springy morph (`toggle`), spits out new ones (`spitPanel`: it flies out of the turtle's mouth and opens on landing, stepping aside from a panel already there, as windows cascade), and sends them into the octopus and back. `step` advances the flights and runs the physics. Swallowed bubbles stay on the stage, out of sight, until the octopus forgets them. It knows nothing of what a bubble shows.
- `Sources/Honu/Stage/Physics.swift`: per-frame motion. Released bubbles keep the pointer's velocity and slow down with friction, idle bubbles drift with a slow per-bubble float, crowded bubbles push each other apart with a damped soft collision that passes momentum on (partial overlaps are allowed so the glass stays visible), and bubbles bounce off the screen edges. Open bubbles can be thrown but neither float nor push, and bubbles in flight or swallowed are left out. It writes a bubble's center and velocity only when they change, so still bubbles cause no redraw.
- `Sources/Honu/Persistence.swift`: `SavedState`, what is kept for the next launch: the turtle's place, which bubbles show which items, where (relative to the screen center), and whether open, plus each microapp's own JSON. The shell makes it (`Shell.snapshot`, saving where a bubble will rest, so one saved mid-flight comes back where it lands) and puts it back when it starts (`Shell.restore`, without the focus, deleting items no bubble showed, such as one still in the octopus). `Autosave` knows nothing of the shell: it decides when and where to write a `SavedState`, and reads it back (`restore`). It checks once a second and writes only what changed; bubbles drifting idly are not a change, but a bubble dragged somewhere is (`moved`). It sorts the keys of each microapp's JSON (`canonical`), since `JSONEncoder` may order them differently from one call to the next.
- `Sources/Honu/Sprites/Sprite.swift`: `PixelGrid`, a character-grid sprite (one character per pixel, `spritePixel` points square), painted by `SpriteCanvas` as crisp squares; `PixelMask` makes hit-testing skip transparent pixels. Sprite animations run on the `now()` clock.
- `Sources/Honu/Animation/`: how things move over time: `Motion` (a bubble's `rise` and `wobble`), `Flight` (a bubble's trip out of the turtle or into the octopus), the easing curves flights follow, and the `now()` clock that animations, the frame tick, the octopus's memory, and autosave run on.
- `Sources/Honu/Extensions/`: what Honu adds to system types, one file per type and purpose (`CGPoint+Arithmetic.swift`, `Color+RGB.swift`).
- `Sources/Honu/Sprites/Turtle.swift`: the turtle, which starts in the bottom-left corner and can be dragged anywhere on screen. It bobs while idle, hops when clicked, and briefly opens its mouth (`spit`) for each bubble.
- `Sources/Honu/Sprites/Octopus.swift`: the octopus. It rises from the bottom edge, in the corner away from the turtle, while summoned or while a swallowed bubble can still come back, and sinks again afterwards. Whether the *pointer* is within `reach` decides a drop, not where the bubble is. It remembers swallowed bubbles for `undoSeconds`, showing "Click to undo"; clicking it or the hint, or ⌘Z, spits the latest back to where it was picked up.
- `Sources/Honu/Views/`: the SwiftUI views. `ShellView` stacks the bubbles, the octopus, the turtle, and the open menu (over a nearly transparent layer, so a press outside closes it) in the `stage` coordinate space. `StageView` draws the bubbles back to front, so the one pressed last (the stage's top) covers the others. They share one `GlassEffectContainer` (without one, Liquid Glass renders untinted), whose spacing is 0 so bubbles never blend; and since the container merges glass shapes that touch and draws all glass beneath all content, each bubble's glass and content are cut away (`StageView.cuts`, `CutAway`) wherever a bubble above it lies, with a `gap`, so the one on top covers the others completely, however see-through its glass. A `GlassEffectContainer` draws its glass above the other views in it, so `glassEffect` must go on the view whose content sits on the glass, never on a separate background layer, or the glass covers the content. Liquid Glass adapts to what is behind the window, so it looks gray in a capture over dark windows; compare renderings against the same backdrop. `BubbleView` draws a bubble as interactive Liquid Glass (whose shape swells while breathing) with its title or symbol, or, open, its title over its microapp's content; dragging moves it and double-clicking toggles it. `TurtleView` and `OctopusView` animate the sprites with `TimelineView`. `TurtleMenu` is a glass menu with one item per microapp (Add Note, Ask AI, Open Web Page) and Exit.
- `Tests/HonuTests/`: Swift Testing tests (`@Test`, `#expect`), run on the main actor and importing the executable target with `@testable import Honu`. They drive the models and controllers directly, not the views: what depends on time takes the time as an argument (the octopus's `swallow`, `spitBack`, and `forget` default to `now()`), and a `Shell` can save to a store of its own (`storeURL`), so persistence is tested against a temporary file.

## Conventions

- Everything in the repository must be in English: identifiers, comments, UI strings, docs, and commit messages — even when the conversation is in Chinese.
- After changing Swift code, run `swift build`, `swift test`, and `swift format lint --strict -r Sources Tests Package.swift` before reporting the work as done, and fix any warnings they raise.
- The Claude API key lives in `.env` at the repository root as `ANTHROPIC_API_KEY` (the name the Anthropic SDKs read). `.env` and `.env.*` are git-ignored; only the empty template `.env.example` is committed. Never read, print, or commit `.env`, and never put a key anywhere else in the repository.
