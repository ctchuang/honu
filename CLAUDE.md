# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Honu is a macOS app written in Swift 6 with **SwiftUI** (hosted in AppKit) — an experiment in desktop GUI design that departs from macOS conventions. Liquid Glass bubbles float directly on the real desktop, above all other windows. It starts with only a pixel-art turtle in the bottom-left corner; clicking it opens a launcher of tiles that make it spit out bubbles (a note, a web page that can also play YouTube videos, a microapp Claude has written, or **+**, a new microapp Claude writes from a description), right-clicking it opens a menu with Exit, and dragging a bubble calls up a pixel-art octopus that deletes it if dropped on, as dragging a microapp's tile there uninstalls the microapp. Every launch is a new instance with data of its own. The launcher's design and plan are in `docs/Launcher.md`. It needs macOS 26 or newer, for Liquid Glass (`glassEffect`) and SwiftUI's `WebView`. The turtle's place, the bubbles, and their items persist across launches in `~/.honu/state.json` (delete it to reset; `~/.honu/` is also where Claude Code runs), or in the file `HONU_STORE` names, so a development run can keep bubbles of its own.

Honu was first written in Rust with egui; that version is in the git history before the switch to Swift.

## Commands

```sh
swift build                  # build
swift run                    # build and launch; bubbles float on the real desktop (quit with ⌘Q)
HONU_STORE=/tmp/honu.json swift run   # same, saving to a store of its own
swift build -c release       # optimized build
swift test                   # run the tests in Tests/HonuTests
swift test --filter <name>   # run tests whose name matches
swift format lint --strict -r Sources Tests Package.swift   # lint (as CI does)
swift format -i -r Sources Tests Package.swift     # format
```

CI (`.github/workflows/ci.yml`) runs on a `macos-26` runner for every push to `main` or `dev` and every pull request: the strict format check (`swift format lint --strict`, so warnings fail), a debug build, the tests, and a release build.

Two hooks run the same checks earlier. `.githooks/pre-push` (on once `git config core.hooksPath .githooks` is set; Git does not turn on a repository's hooks by itself) runs the strict lint and the tests before a push that changes `Sources/`, `Tests/`, `Package.swift`, `Package.resolved`, or `.swift-format`, retrying `swift test` with Swift Testing's plugin path when SwiftPM loses it. A Claude Code `PostToolUse` hook in `.claude/settings.json` lints each Swift file Claude writes or edits and hands the errors back, so they are fixed as they appear; it does not run the tests, which are still to be run before reporting work as done.

`.swift-format` sets 4-space indentation and 100-column lines. The project is a Swift package, so it builds with the Command Line Tools alone; Xcode is not needed. The Command Line Tools do not ship SwiftUI's macro plugins, so **`@State` and other SwiftUI macros do not compile**: spell state out as a stored `State` value instead (`private let player = State(initialValue: Player())`, read through `wrappedValue`), or keep it in an `@Observable` model (Observation's macros do ship). With the Command Line Tools alone, SwiftPM sometimes fails to hand the compiler Swift Testing's macro plugin, and `swift test` fails with "plugin for module 'TestingMacros' not found"; pass it by hand: `swift test -Xswiftc -plugin-path -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing`. `swift run` launches a bare executable, not an app bundle; the Dock icon is set at launch from `Sources/Honu/Resources/icon.png`.

## Architecture

The code follows MVC. Each **microapp** (Notes, Ask AI, Web, Maker; Ask AI keeps its chats but is left off the launcher) is a controller that keeps its own model: any number of items, such as notes. A **bubble** is only a view of one item, pointing at it by id. The **shell** wires microapps, the stage of bubbles, and the two sprites (the turtle and the octopus) together. Models are `@Observable` classes on the main actor, so SwiftUI views redraw when what they read changes.

The folders follow the layers: `App/` hosts SwiftUI in AppKit, `Shell/` is the controller of the whole app (with the `InputRouter`), the models are in `Stage/` (the bubbles), `MicroApps/`, and `Sprites/`, and the SwiftUI views are in `Views/` (each microapp's own views sit in its folder). `Animation/` and `Extensions/` hold what the rest shares.

- `Sources/Honu/App/main.swift`: starts `NSApplication` with `AppDelegate` as a regular app (Dock icon and menu bar).
- `Sources/Honu/App/AppDelegate.swift`: sets the Dock icon and the menu bar (Quit and the Edit commands, Undo and Redo among them, which text fields and web pages need), creates the `Shell` and the `FloatingWindow` covering the main screen's visible frame (everything but the menu bar and Dock), and starts the `FrameClock`, which calls `Shell.tick` and `ClickThrough.update` every frame. A local event monitor turns what SwiftUI's gestures do not cover into `InputEvent`s for the `InputRouter`, with whether the keyboard goes to a text field or a web page (`isTyping`), so type-ahead and ⌘Z leave those alone. It saves once more when Honu quits.
- `Sources/Honu/App/FloatingWindow.swift`: `FloatingWindow`, a transparent, borderless, shadowless window at the floating level that stays on the Space Honu was launched on, hosting `ShellView` in an `NSHostingView` that does not resize the window to fit. It can become key, which borderless windows refuse by default but text fields need. `ClickThrough` lets clicks through to the apps below except where `Shell.takesClick(at:)`; a window that ignores mouse events gets none, so it polls the global mouse position each frame to decide.
- `Sources/Honu/App/FrameClock.swift`: `FrameClock`, a `CADisplayLink` on the window that calls back once per frame of the display (60 or 120 times a second), in the common run loop mode so it keeps running while a drag or menu tracks. Everything that moves takes the time since the last frame, so the frame rate does not change how fast things go.
- `Sources/Honu/Shell/Shell.swift`: `Shell`, the controller of the whole app (what it gives the views is in `Shell+Views.swift`, and its `snapshot` and `restore` in `Shell+Saving.swift`): the `Registry` of microapps (and the `maker`, which the launcher's **+** starts), the `Stage`, the `Turtle`, the `Octopus`, and what the turtle has open (`popup`: the launcher, or the system menu with Exit). What is under a point is one `Hit`, from the top layer down: an open popup (which takes every click, like a native menu), the turtle, the octopus, then the bubbles. Clicking the turtle hops it and opens the launcher there (`clickTurtle`; `rightClickTurtle` opens the system menu); a `LauncherTile` starts a new item (`choose`): of a built-in microapp (`start`), of an installed microapp (`launch`), or a new microapp to describe, and the turtle spits out a bubble showing it (`spit`). Dragging a bubble more than `summonDistance` calls up the octopus; with the pointer within its reach the bubble shrinks, and letting go there swallows it. Dragging an installed microapp's tile does the same (`dragTile`, `endTileDrag`; built-in tiles wobble instead): dropped on the octopus, the tile goes down its mouth (`swallowedTile`) and the microapp is uninstalled (`uninstall`), the octopus swallowing it with every bubble of it in one gulp. An installed microapp's tile also has a right-click menu with Uninstall (`uninstall(_:from:)`, the tile going down the octopus's mouth from where it is, without asking, since it can be undone). `undoDelete` has the octopus spit the latest gulp back, putting an uninstalled microapp's tile back too. `tick` lets the microapps catch up (setting each bubble's breathing from `isBusy` and playing the motions they ask for), steps the stage by the time since the last tick (at most 1/30 s), deletes for good what the octopus forgets (bubbles, and their items once no bubble shows them, and uninstalled microapps), and autosaves. The views read the models (the stage's bubbles, the sprites) but act only through the shell, and ask it what a bubble shows (`appearance`, `title`, `content`) and what the launcher lists (`launcherTiles`), so they never reach into the microapps.
- `Sources/Honu/Shell/InputRouter.swift`: `InputRouter` turns the input SwiftUI's gestures do not cover into calls on the shell: presses on content AppKit views take for themselves (to raise that bubble, while the press goes on), right-clicks on the turtle (opening the system menu; on the launcher, `launcherFrame`, they go on to its tiles' menus, even over the turtle; elsewhere they close any popup), Escape (closing a popup), printable keys while no text field has the focus (type-ahead), and ⌘Z (undoing a delete, unless a text field has the focus). It takes `InputEvent`s rather than `NSEvent`s, so the rules are tested without AppKit. Everything else comes in through the views' gestures, and `ClickThrough` decides where clicks go.
- `Sources/Honu/MicroApps/`: the `MicroApp` protocol and one folder per microapp, the controller and its model apart from the views (and the view states, which belong to one bubble each).
- `Sources/Honu/MicroApps/MicroApp.swift`: the `MicroApp` protocol and what goes with it. A bubble's `ViewTarget` (`AppID` + `ItemID`) names one item, so a microapp can have any number of bubbles. `MicroApp` is three smaller protocols and a little more: `ItemStore`, what it keeps (its `items`, which it creates, removes, and saves and loads as JSON, keeping their ids; `ItemIDs.skip(past:)` keeps new ids after restored ones, and an `ItemTable` (`ItemTable.swift`) does all of this for a value per item, as every microapp uses it); `ItemLook`, how they look (`appearance`: glass tint, symbol, sizes, text color; `title`, the bubble label; `isBusy`, breathing); and `ItemViews`, the SwiftUI `content` of an open bubble. It also has its `id`, its launcher tile's `launcherLabel` and `launcherSymbol`, and whether the launcher lists it (`isLaunchable`), and catches up on background work in `update`, where it can ask, through its `Context`, for `Effect`s on the bubbles showing an item, such as a `Motion` for every one of them. Each bubble also owns a view state its microapp makes for it (`newViewState`), for what belongs to that one view rather than to the item, such as whether it still has to take the focus; its type is the microapp's `ViewState` (`NoViewState` if it keeps nothing), and `content` and `typeAhead` take it typed. The shell holds view states untyped, and goes through `anyContent` and `anyTypeAhead`, the one place they are cast. A view state that is `FocusTaking` takes type-ahead: text typed while no field has the focus goes to the newest bubble the turtle spat out (`Shell.type`), as long as its `focusPending`, and its microapp puts it in the field it shows first (`typeAhead`); when the field takes the focus, a view takes it once with `takesFocus`, and `placeCursorAtEnd` (both in `Views/Focus.swift`) keeps the text from being selected and typed over. `Registry.swift` holds the microapps in launcher order and routes a target to its microapp, and `shortLabel` (`ShortLabel.swift`) shortens titles. To add a microapp, give it a folder in `Sources/Honu/MicroApps/`, implement the protocol there, and list it in `Shell.init`.
- `Sources/Honu/MicroApps/Notes/`: the Notes microapp (`NotesApp.swift`; the view, `NoteEditor.swift`), any number of notes, each a `TextEditor` on yellow-tinted glass; a new note's bubble takes the focus when it opens. A note's bubble is labeled with its first line with text (`shortLabel` keeps labels short).
- `Sources/Honu/MicroApps/Ask/`: the Ask AI microapp, left off the launcher (asking Claude is to become feeding a bubble to the turtle) but keeping its chats (`AskApp.swift`; the model, `Chat.swift`; the view, `ChatView.swift`), any number of `Chat`s, each shown through a `ChatView` with a `FocusRequestState` (`Views/Focus.swift`, which Maker shares: whether to take the focus; a chat counts up `focusRequests` when the user has to type again, and each view takes the focus once per request). A chat asks for a question, then shows the answer as it streams in; the view measures its content (`contentHeight`), and the chat's `appearance` asks for a panel that fits it, between `startHeight` and `maxHeight`, which the shell applies. `update` polls every chat's stream and turns how a question ended (`Outcome`) into a `rise` or `wobble`, and `isBusy` makes a chat's bubbles breathe while Claude works. A question still being answered when Honu quits is saved as interrupted.
- `Sources/Honu/Claude.swift`: asks Claude through the `ClaudeClient` protocol. A `ClaudeRequest` is a prompt, a system prompt, and an effort; Ask AI's system prompt is `Chat.systemPrompt`, and the Maker's is `MakerPrompt.system`. `ClaudeCode` runs the Claude Code CLI headless for each request (`claude -p`, the prompt on standard input, `arguments(for:)`: `stream-json` output with partial messages, `claude-opus-5-5` at the request's effort, no tools, no saved session), so Honu needs no API key: Claude Code signs in with the user's Claude account. It finds `claude` in `PATH` or the folders it is usually installed in (`executable`), since an app opened from the Finder has no shell `PATH`, runs it in `~/.honu/` (`workingDirectory`, created if missing) so no project's CLAUDE.md comes along, and leaves `ANTHROPIC_API_KEY` out of its environment. `EventParser` turns its JSON lines into `ClaudeEvent`s: the Messages API's text deltas passed on as `stream_event`s, and the closing `result`; `claude` exiting without one fails with what it wrote to standard error. Standard error is read alongside the answer, on a thread of its own, since a full pipe would stall `claude` mid-answer, and its exit is awaited through `terminationHandler` rather than a blocked thread; tests run `receive` on a stand-in shell script. Cancelling the stream terminates `claude`. Events go into an `AnswerStream`, a locked queue the main actor drains each frame (`take`), as the Rust version's channel did, so tests feed it by hand (`FakeClaude` in the tests).
- `Sources/Honu/Services.swift`: `Services`, what the microapps share: the `ClaudeClient`. `Shell.init` takes the services, so tests can pass a fake.
- `Sources/Honu/MicroApps/Web/`: the Web microapp (`WebApp.swift`, with `LoadEnd`; what a link shows, `PageSource.swift`; the views, `WebContent.swift` and `PageView.swift`), any number of pages. A new page asks for a link, then `PageView` shows it in a `WebPage` in SwiftUI's `WebView`; YouTube links (`youTubeID`, `PageSource`) play in YouTube's embedded player, loaded from an HTML page with a base URL, because the player refuses to play without a referring origin. `PageView` tells the microapp when it starts and stops loading (`startedLoading`, `stoppedLoading`), with how the load ended (`LoadEnd`), so a page's bubbles breathe while it loads, rise once it has, and wobble if it failed; a load given up (the bubble closed, or a new navigation replaced it) does neither. `LoadEnd` unwraps `WebPage.NavigationError` to tell the two apart. Only the first load counts, not following links.
- `Sources/Honu/MicroApps/Maker/`: the Maker microapp (`MakerApp.swift`; the models, `GeneratedApp.swift` and `Instance.swift`; the views, `MakerView.swift` and `MicroappView.swift`), any number of microapps Claude writes (`apps`), each running in any number of `Instance`s, the items its bubbles show: an instance has its `GeneratedApp`, its own saved state (`dataID`, `dataURL`), and the size its page asked for, which a new page resets. A microapp is installed once its first page is written (`hasPage`; `library` lists the installed ones, which the launcher shows), and stays when its last instance is deleted; `launch` starts another instance of it, its page running at once. One never made goes to the Trash with its last bubble. Uninstalling goes through `withdraw` (out of the library while the octopus can still bring it back, and not saved, so quitting finishes it), then `reinstate` or `uninstall` (deleting it, its instances, and its folder). A new one asks for a description, then Claude writes a page that does it (`MakerPrompt`: one self-contained HTML file, at medium effort), which `WritingPreview` shows streaming in; `AppSource` finds the page in the answer (Claude may wrap it in a Markdown fence; a page cut off is no page) and reads what it says about itself in its head (`PageMeta`: its `<title>`, the size it wants in `honu-size`, and its closed bubble's SF Symbol in `honu-symbol`). The page then runs in the bubble, which fits its size, with a `ChangeBar` below for asking Claude to change it (its field, sent with Return or its Go button; the draft is cleared once a page is made or changed), fixing the errors it reported, and undoing the last change; all of these change the microapp, so every instance of it loads the new page, and the draft is shared. A `GeneratedApp` goes from `describing` to `writing` (`making`, `changing`, or `fixing`) to `running`; a page that fails to come back leaves the page before it running with a `notice`, or, without one, asks for the description again. Errors the page reports within `fixWindow` of loading are fixed once without asking, a second after the first (`fixDelay`), unless the page is itself a fix; later ones wait for the user. The bubbles of every instance rise once a new page loads (`loaded`) and wobble when writing fails. Each microapp is a folder of its own (`AppFolder`, named by a UUID, not the item id, which restarts with a new store) under `~/.honu/microapps/`, or `<name>.microapps/` beside the file `HONU_STORE` names (`MakerApp.root`), holding its page (`index.html`), what each instance saves (`instances/<uuid>.json`), and the pages before each change (`history/`). The store keeps each microapp's folder, description, and draft, and each instance's microapp, data file, and size (`{ apps, instances }`); a store from before instances, an array of microapps with one `data.json` each, is upgraded on load (`upgrade`). Loading moves to the Trash the folders no microapp has, and deletes the data files no instance has. `MicroappView` runs the page in a `WebPage` served by `MicroappScheme` at `honu-app://<folder>/`, so each has an origin of its own, a secure context, and relative links (the scheme never serves outside the folder, nor anything in `instances/`, compared without case, so a page reaches only its own data), and loads it again for each new `version`; `StaysHome` keeps the page from navigating away, opening links in the browser instead. `Bridge` gives the page `window.honu`: `load` and `save` (its state, in its instance's file), `fetch` (http and https through `URLSession`, past CORS), and `resize`, and hears of its errors (`error`, `unhandledrejection`, `console.error`).
- `Sources/Honu/Stage/Bubble.swift`: `Bubble`, the view model of one bubble: its target, center, velocity, float `phase`, whether open, and whether doomed or swallowed. Its outline is a continuous-corner rounded rectangle (`cornerRadius`; `drawnFrame` is where it is drawn this frame), and `contains` hit-tests that outline as drawn, so presses past its rounded corners go to whatever is below. Bubbles show what they are doing through motion: `isBusy` makes one breathe (only the glass swells, `swell`, so content and hit-testing hold still), and `play` runs a short `Motion` that moves the whole bubble and returns it: `rise` when a task finishes, `wobble` when the user is needed. A bubble flying out of the turtle, back from the octopus, or into it follows a `Flight` of its own instead of the physics or the pointer: `fly` pops it out small and grows it (with a little overshoot) on the way, opening it on landing if asked, and `swallow` shrinks it into the octopus's mouth. `animate` advances the flight each frame; `destination` is where it will rest.
- `Sources/Honu/Stage/Stage.swift`: `Stage`, every bubble in back-to-front paint order. The stage hit-tests, raises, drags (the dragged bubble stays on top, takes the pointer's velocity so it glides when let go, and new bubbles go below it), opens and closes bubbles with a springy morph (`toggle`), spits out new ones (`spitPanel`: it flies out of the turtle's mouth and opens on landing, stepping aside from a panel already there, as windows cascade), and sends them into the octopus and back. `step` advances the flights and runs the physics. Swallowed bubbles stay on the stage, out of sight, until the octopus forgets them. It knows nothing of what a bubble shows.
- `Sources/Honu/Stage/Physics.swift`: per-frame motion. Released bubbles keep the pointer's velocity and slow down with friction, idle bubbles drift with a slow per-bubble float, crowded bubbles push each other apart with a damped soft collision that passes momentum on (partial overlaps are allowed so the glass stays visible), and bubbles bounce off the screen edges. Open bubbles can be thrown but neither float nor push, and bubbles in flight or swallowed are left out. It writes a bubble's center and velocity only when they change, so still bubbles cause no redraw.
- `Sources/Honu/Persistence.swift`: `SavedState`, what is kept for the next launch: the turtle's place, which bubbles show which items, where (relative to the screen center), and whether open, plus each microapp's own JSON. The shell makes it (`Shell.snapshot`, saving where a bubble will rest, so one saved mid-flight comes back where it lands) and puts it back when it starts (`Shell.restore`, without the focus, deleting items no bubble showed, such as one still in the octopus). `Autosave` knows nothing of the shell: it decides when and where to write a `SavedState`, and reads it back (`restore`). It checks once a second and writes only what changed; bubbles drifting idly are not a change, but a bubble dragged somewhere is (`moved`). It sorts the keys of each microapp's JSON (`canonical`), since `JSONEncoder` may order them differently from one call to the next.
- `Sources/Honu/Sprites/Sprite.swift`: `PixelGrid`, a character-grid sprite (one character per pixel, `spritePixel` points square), painted by `SpriteCanvas` as crisp squares; `PixelMask` makes hit-testing skip transparent pixels. Sprite animations run on the `now()` clock.
- `Sources/Honu/Animation/`: how things move over time: `Motion` (a bubble's `rise` and `wobble`), `Flight` (a bubble's trip out of the turtle or into the octopus, which a tile dropped on the octopus follows too; `after` gives it some time after it started), the easing curves flights follow, and the `now()` clock that animations, the frame tick, the octopus's memory, and autosave run on.
- `Sources/Honu/Extensions/`: what Honu adds to system types, one file per type and purpose (`CGPoint+Arithmetic.swift`, `CGSize+Arithmetic.swift`, `Color+RGB.swift`, `Color+Error.swift`).
- `Sources/Honu/Sprites/Turtle.swift`: the turtle, which starts in the bottom-left corner and can be dragged anywhere on screen. It bobs while idle, hops when clicked, and briefly opens its mouth (`spit`) for each bubble.
- `Sources/Honu/Sprites/Octopus.swift`: the octopus. It rises from the bottom edge, in the corner away from the turtle, while summoned or while something swallowed can still come back, and sinks again afterwards. While summoned, a comic speech bubble (`SpeechBubble`, in `SpriteViews.swift`) beside it offers to recycle the dragged bubble or uninstall the dragged tile's microapp (`offersHelp`, `offer`). Whether the *pointer* is within `reach` decides a drop, not where the bubble is. Each gulp it swallows (`Swallowed`) is bubbles, each with where it was (`Morsel`), and the microapp uninstalled with them, if any. It remembers them for `undoSeconds`, showing "Click to undo"; clicking it or the hint, or ⌘Z, spits the latest gulp back, and `forget` hands over what is too old to bring back.
- `Sources/Honu/Views/`: the SwiftUI views. `ShellView` stacks the bubbles, the octopus, the turtle, the open popup (over a nearly transparent layer, so a press outside closes it), and a tile dragged out of the launcher or going down the octopus, in the `stage` coordinate space. `StageView` (`StageView.swift`) draws the bubbles back to front, so the one pressed last (the stage's top) covers the others. They share one `GlassEffectContainer` (without one, Liquid Glass renders untinted), whose spacing is 0 so bubbles never blend; and since the container merges glass shapes that touch and draws all glass beneath all content, each bubble's glass and content are cut away (`StageView.cuts`, `Cut`, and `CutAway`, all in `StageView.swift`) wherever a bubble above it lies, with a `gap`, so the one on top covers the others completely, however see-through its glass. A `GlassEffectContainer` draws its glass above the other views in it, so `glassEffect` must go on the view whose content sits on the glass, never on a separate background layer, or the glass covers the content. Liquid Glass adapts to what is behind the window, so it looks gray in a capture over dark windows; compare renderings against the same backdrop. `BubbleView` draws a bubble as interactive Liquid Glass (whose shape swells while breathing) with its title or symbol, or, open, its title over its microapp's content; dragging moves it and double-clicking toggles it. An open bubble's content sits in an `UndoScope` (`UndoScope.swift`), an AppKit view in the responder chain with the bubble's own undo history (`Shell.undoManager(for:)`), since the window has one for all bubbles, SwiftUI's `undoManager` cannot be set, and its text views keep the first one they find; it also undoes for web pages, which leave Undo to the next responder. `TurtleView` and `OctopusView` (`SpriteViews.swift`) animate the sprites with `TimelineView`; the octopus's pauses while it is out of sight. `LauncherView` is the turtle's launcher, a glass panel of tiles, four to a row, which grows with its tiles and scrolls past three rows (`size(for:)`, kept on screen by `menuCorner`): Note, Web Page, the installed microapps, and New Microapp (**+**); a tile (`TileView`, showing a `TileFace`) is clicked to start what it starts, and dragged (an installed microapp's) or wobbled (the others); an installed microapp's tile has a `contextMenu` with Uninstall. `SystemMenu` (`Menus.swift`) is the right-click menu with Exit, made of `MenuItem`s.
- `Tests/HonuTests/`: Swift Testing tests (`@Test`, `#expect`), run on the main actor and importing the executable target with `@testable import Honu`. They drive the models and controllers directly, not the views: what depends on time takes the time as an argument (the octopus's `swallow`, `spitBack`, and `forget`, and the shell's `uninstall` and `endTileDrag`, default to `now()`), and a `Shell` can save to a store of its own (`storeURL`), so persistence is tested against a temporary file.

## Conventions

- Everything in the repository must be in English: identifiers, comments, UI strings, docs, and commit messages — even when the conversation is in Chinese.
- After changing Swift code, run `swift build`, `swift test`, and `swift format lint --strict -r Sources Tests Package.swift` before reporting the work as done, and fix any warnings they raise.
- Honu asks Claude through the user's Claude Code login and uses no API key. `.env` and `.env.*` stay git-ignored so an old key file is never committed; never read, print, or commit one, and never put a key anywhere in the repository.
